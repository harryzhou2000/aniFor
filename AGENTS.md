# AniforTPT agent guidance

## CodeGraph

When `.codegraph/` exists, use `codegraph explore` before grep/find or broad file reads when locating or understanding code. Ask it for the relevant symbols, complete source, and call paths. Use `rg` only after CodeGraph has established the area to inspect.

## Viewport, input, and rendering

Before changing viewport layout, pointer mapping, zoom/pan, Pixi setup, shader coordinates, canvas sizing, or device-pixel-ratio behavior, read [`docs/viewport-rendering-contract.md`](docs/viewport-rendering-contract.md).

The non-negotiable contract is:

- The simulation world is 612×384 cells.
- World, brush, and semantic texture coordinates use that same unscaled space.
- Layout performs one uniform aspect fit; camera zoom/pan performs one presentation transform.
- Coalesce viewport fitting through `requestAnimationFrame` from the frame `ResizeObserver`, `window.resize`, `visualViewport.resize`, and compact-media changes. A frame can change during an in-place desktop resize without a timely observer delivery; never rely on one resize signal alone.
- Device pixel ratio affects backing resolution only, never world or CSS coordinate math.
- The default render backing is 2× per axis (1224×768 for the 612×384 world). `?renderScale=1` remains the low-resolution A/B diagnostic; `?renderScale=4` and `?renderScale=8` request true contour supersampling (2448×1536 and 4896×3072 for the canonical world). Canonical WebGL 8× is supported inside the explicit 8,192-axis/16,777,216-pixel single-target budget. Disable redundant MSAA and the extra high-quality diagonal/ring shader probes at 8×, keep the temporary automatic Canvas fallback within the separate 4,096-axis/8,388,608-pixel budget so startup never duplicates 60 MiB targets, and expose requested/effective scale in the backend HUD/datasets. Keep that Canvas mounted during a bounded 30-second cold 8× WebGL warm-up; 1×–4× retain the normal 10-second promotion window. A slow first 15-million-fragment draw is not evidence that 8× is unsupported. The browser gate must prove effective 8×, exact 4896×3072 backing, zero browser errors, and CSS geometry byte-for-byte equivalent to the same 2× viewport; backing scale never enters pointer/camera math.
- Pixi filter `vTextureCoord` is not a world UV. The semantic field shader must use the sprite-local `vFieldCoord` supplied by `FIELD_VERTEX`.
- Native TPT walls are a separate `bmap`-derived field and texture. Never encode a wall ID as a particle/material ID; particles and walls may coexist at the same world cell and must be composited independently.
- Simulation tools are neither particles nor walls. Brush tools consume sampled points; vector tools consume raw consecutive grid segments and must explicitly no-op in the point path so they never fall through to the selected particle brush.
- Configured sources are semantic tools, not ordinary source-particle brushes. Keep their emitter and retained target explicit, route them through the native `CtypeDraw` boundary after erase/tool handling and before ordinary paint, and return without fallback even when the capability is absent. Preserve the target as native particle `ctype` in OPS saves; do not mirror it in a JavaScript world map.
- TPT LIFE presets are semantic tools, not generic material IDs. IDs 171–194 are render projections of `PT_LIFE` ctypes 0–23; place them only through `powder_set_life`, keep occupied cells atomic, return without ordinary-paint fallback, and preserve native `ctype` in OPS saves. Never pass a LIFE projection ID through `powder_set` or use the LIFE brush as a configured-source shortcut.
- Headless Wind clears inactive particle-authored coarse `vx`/`vy` when a new gesture epoch begins, writes the authored velocity before `BeforeSim`, enables `AIR_ON` for exactly that update, then restores `AIR_VELOCITYOFF` before particle advection. Never inject Wind after `BeforeSim`: that bypasses diffusion, pressure coupling, clamping, and air-blocking walls. Preserve unstepped Wind through the namespaced optional OPS marker instead of inferring it from ordinary imported-save velocity.
- The shared liquid texture is species-aware RGBA: RGB is the uniquely supported liquid color and alpha is density. Do not read red as density or choose a liquid halo color by fixed neighbor scan order; exact unlike-liquid ties must remain a visible interface.
- Canvas dense-liquid cohesion is RGB-only and interior-only. Require high field and liquid-plane alpha, one exact smooth-eligible liquid species on all four cardinals, and at least one matching diagonal; world borders, shorelines, narrow streams, unlike species, trait-bearing liquids, and emissive liquids must remain unsmoothed. A cardinal empty cell may count only when it is an already reconstructed, high-density canonical-species pinhole. Read donors from the persistent three-row pre-smoothing ring and persistent per-source-row views so the result cannot cascade with scan order or allocate subarray views per frame, and preserve every alpha/material/density byte exactly.
- Dense-liquid lighting is field-owned even though alpha/support remains semantic and reconstruction-owned. In Canvas, scale raw-cell contour light down only when centre field alpha proves cohesion, and allow local top glints only when the semantic top is empty and the field above is genuinely sparse; unlike materials are seams, not air surfaces. Connected semantic cells and reconstructed holes share one hue-preserving relief basis derived from centre plus four-cardinal field alpha: upper-left slope, convex crown, and concave pocket response must be bounded, allocation-free, and gated off for isolated droplets. A dense unlike-liquid semantic contact may additionally derive a bounded signed optical interface from canonical field RGB contrast. Gate that work behind the already-known unlike-liquid neighbour so ordinary dense pool cells retain the alpha-only fast path; require high alpha on both samples, never average species RGB, and change neither ownership nor silhouette. Exposed non-emissive liquid surfaces may reflect the shared emission field: first require a semantically empty cardinal side, then validate that side against liquid-field alpha so dense pinholes do not become reflectors. Canvas may use the existing clamped bilinear light sample with a bounded liquid response gain; WebGL must reuse its current emission sample plus already-computed top-lip, rim, Fresnel, and surface-normal terms, with no extra texture fetch. Semantic cells may scale the relief basis by their authoritative optics class; reconstructed empty support keeps the default gain. Keep Lava's body glow in the shared emission field and disable local emission feedback on emissive liquid so the twice-composited light plane cannot clip the whole body. In WebGL, promote lighting depth and suppress semantic micro-normals only when both centre density and the four-cardinal field mean prove connected support. Reuse the same four existing `vec4` liquid samples for species-contact normals and a restrained meniscus multiplier; add no texture read. Dense WebGL body relief may recombine the already computed broad-sheen and caustic-wave signals only as a centred, liquid-depth-gated RGB multiplier with optics-specific gains; do not add a wave, field, pass, or alpha/support change. Never use this RGB-lighting decision to widen alpha, mix neighbouring species RGB, or flatten an isolated droplet.
- Canvas gas relief is a presentation-only transform of the shared atmosphere texture: preserve alpha byte-for-byte, keep self-relief as a uniform RGB scale, and permit only bounded additive colour from the existing emission field. Dense WebGL gas should blend toward atmosphere RGB instead of exposing raw semantic-particle dots. Curvature relief must reuse the same four cardinal atmosphere-alpha samples as the density slope: brighten bounded convex crowns and shade concave overlap pockets. Canvas may select the outward-facing one of the four emission neighbours it already reads. Desktop/high-quality WebGL may take at most one additional emission sample along the reconstructed outward normal; compact/mobile quality must take none. Directional light must add no field, pass, persistent buffer, neighbouring gas-RGB read, or support/alpha change. Re-style Canvas atmosphere whenever either atmosphere or emission rebuilds so field lighting cannot remain stale.
- Once the atmosphere field has support, it owns gas mass, colour mixture, and macro silhouette; the exact semantic gas plane is only a bounded species/emissive accent. Canvas may take one allocation-free bilinear atmosphere-alpha sample per semantic gas world cell, never per supersampled output pixel. WebGL must reuse the atmosphere sample already in the shader and suppress exact clean/sooty optics or velocity detail as field ownership rises. Add no gas-only texture, target, upload, pass, or 8× resource class. Retain deterministic sparse Smoke/FOG/CFLM chains with carrier/midpoint/gap probes plus compact FOG/CFLM topology, microcontrast, hue, exposure, and Canvas/WebGL parity gates. A high render scale must not turn supported gas back into beads or fill an authored gap.
- Treat reconstructed volume density as silhouette support, not automatic opacity. Gas optical depth may darken RGB but must not widen its alpha. For liquids, derive optical depth from authoritative semantic occupancy plus local field support, keep reconstructed density for joined edges/holes, and use local slope for lips or depth rather than absolute world position. WebGL may promote depth only from its four already-sampled liquid neighbours so isolated droplets stay sparse; Canvas reconstructed holes may inherit RGB only from styled semantic neighbours of the uniquely supported liquid species.
- The palette lookup alpha byte stores `RenderOptics`; the style lookup alpha byte stores `RenderTrait`. Keep both textures nearest-sampled with `no-premultiply-alpha`. Optical classes normally change RGB absorption, scatter, or gloss only. `TranslucentRigid` is the explicit presentation-alpha exception; it still cannot affect support, cavity eligibility, physics, or material ownership. Reconstructed empty-space support must keep the default class rather than guessing a material.
- Solid cavity reconstruction is a separate presentation-only alpha decision. Reconstruct only an interior exact solid material with zero different nonempty immediate neighbours, using either four-cardinal enclosure or at least five of eight matches with three cardinal supports. A two-opposing-cardinal thin crack is allowed only when all four matching diagonals prove continuous side walls and the missing axis is bounded by the same exact material two cells away; keep the distance-two bounds explicit so sparse crosses, clamped world edges, and mixed seams cannot qualify. Canvas must read the immutable semantic grid so fills cannot cascade, averaging ordinary matching styled pixels but using canonical palette RGB for trait-bearing solids. WebGL reuses its eight immediate samples and ordinarily branches to only the applicable pair of distance-two crack reads. Its high-quality exact 2×2-cavity exception may stage seven outer-perimeter reads only after proving the five-neighbour/two-adjacent-cardinal topology, empty opposite diagonal, zero foreign neighbours, and explicit inner/outer bounds; it must never become a general ring search. Eligibility remains conservative and unchanged when tuning accepted-cavity appearance: once exact-material support qualifies, map its confidence into only the 0.90–0.98 display-opacity band. WebGL may apply that normalization only when `surfaceOnly` is set and reconstructed `density` is nonzero; nearby exact material alone is not proof of a cavity. Preserve powders, unlike-material seams, native walls, world borders, sparse crosses, and open notches. The browser gate must hold solid-tile dark-pit fraction at or below 0.08 and require negligible blank-differenced signal in both matrix separators; raw dark RGB is not separator evidence on an opaque page. This closes proven cavities more convincingly; it does not establish that all cellularity has been removed. Never extend role traits into reconstructed empty cells.
- Dense solid relief is RGB-only and requires the exact same semantic material on all four cardinal neighbours. Keep its single cubic-smoothed triangle lookup module-static and per-frame allocation-free, with the matching analytic GLSL slope: smooth rigid uses axis `(2,1)`, organic `(1,4)`, device `(4,0)`, and radioactive `(3,-2)`; rough/granular matter gets zero dense macro relief. Attenuate cell-frequency family texture only inside proven dense interiors, keep trait/emissive accents authoritative, and uniformly compress over-range highlights for bright-canonical Canvas solids so a vivid channel such as DTEC red does not framebuffer-clip. Preserve silhouettes/alpha/powder granularity/unlike-material seams, and do not add a solid field, second wave, texture/neighbour sample, or full-grid presentation pass. The composed gate must keep all solid-family samples at microcontrast no greater than 9 with macro luma range at least 7, while dense Sand retains microcontrast at least 3. In WebGL, reuse the already decoded family/emission metadata and retain the low-quality discrete-shape early return.
- Curved 2× WebGL boundaries use the four existing compatible-occupancy samples with monotone cubic Hermite weights `t²(3−2t)` and analytic derivative `6t(1−t)`. The one-dimensional weight integral stays 0.5, but that fact alone does not prove final thresholded raster area. Prefer this local estimator to a full-screen blur, convolution, mesh, or SDF when smoothing solid/liquid silhouettes. Do not widen native walls, merge unlike liquid RGB/species, or apply the estimator to gas/energy topology. Coverage compactness alone is not proof of a good edge; retain exact curved fixtures, blank-differenced species seams, normalized area/outer-ring/topology controls, isolated particle controls, and a real runtime-GLSL screenshot. The browser gate must also measure final composed 20/50/80% threshold crossings against an analytic curved endcap, bounding RMS/max distance, transition width, bilateral symmetry, and monotonicity. Canvas keeps its separate bounded compatibility contours, but it must pass that same composed crossing contract before claiming visual parity.
- Solid contour depth may derive signed mean curvature from those same four Hermite occupancy samples and the analytic second derivative `6−12t`. Apply it only to real, non-emissive solid-family contour pixels; straight edges and dense interiors must be exact no-ops, granular/powder matter gets zero gain, and family gains remain bounded. Change RGB only—never coverage, alpha, material ownership, cavity eligibility, or support. Canvas must reject dense cells once per world cell before supersampled evaluation so 8× does not pay curvature work across whole bodies. Keep matched rounded/notched rigid, organic, and device fixtures plus independent off→on→off captures; require bounded response at convex/concave edges, exact repeatability, and byte-identical support.
- Powder has two visual scales and three user-comparable styles. `Grains` forces every occupied powder cell to one exact square cell and forbids empty-side promotion; `Local` keeps the stability-owned short analytic contour but ignores the long field; `Smooth` adds the shared slope field and is the default. Keep the single accessible Grains/Local/Smooth control synchronized across Canvas and WebGL. The browser gate must click all three exclusive states, require distinct binary silhouette signatures (not only RGBA/shading signatures), prove Grains has less reconstructed area/macro relief than Smooth, and return to a byte-identical Smooth signature. Judge the isolated Grains cell again at maximum viewport zoom, requiring a near-square, highly filled multi-pixel box in both composed backends; the exact raster unit test still pins its one-cell source coverage. A one-byte-per-cell presentation stability field owns the transition: retain the exact semantic owner, require at least two compatible powder/solid neighbours, advance only below native speed 3, hold between 3 and 10, and release immediately at speed 10 or lost contact. Static backends without velocity may settle supported powder immediately. Settled powder supplies a shared full-resolution slope field: two allocation-free horizontal radius-10 box passes form a triangular long tangent, the tight five-tap vertical pass preserves pile height, and packed RGBA stores density, signed gradients, and local solid/powder support for both Canvas and WebGL. In Smooth mode, blend the wide field only on top/slope-facing gradients and only for a genuinely deep exact-material heap: occupied powder needs two cells below plus lateral support; empty projection needs three below. Preserve a Local-derived opacity floor of 40% on every semantically occupied deep-heap subpixel so columns and irregular piles cannot lose visible sections; this floor changes coverage only and leaves wide-field RGB/relief styling available above it. This preserves one- and two-cell Clay/Concrete ridges, branches, ledges, and deep notched columns while bulk slopes remain smooth. Exact semantic ownership and the one-cell presentation-growth limit remain authoritative. Unlike powders may share categorical powder-phase coverage at contact, but exact material RGB stays exclusive and ambiguous empty-side candidates are rejected. Long blur input is stable powder only; solids may contribute local support but must not enter the tangent field, and walls must contribute neither. A powder may borrow solid support at rest, but a solid accepts only solid support so gas, liquid, and moving powder never wobble its edge. Rebuild only after relevant state changes at the bounded powder cadence, reuse preallocated storage, and never reuse solid-cavity opacity, blur the whole solid plane, or use first-cardinal scan order to choose an unlike powder. Keep the exact shallow-slope render-lab fixture, field stair-energy test, and full-cell semantic comparison of both notched Clay/Concrete columns against Local: every occupied cell centre must remain visible, all authored empty cells are measured, and deep notch cells must remain empty. Retain dense-Sand microcontrast, maximum-zoom square-Grains evidence, and a real runtime-GLSL screenshot before claiming Canvas/WebGL parity.
- `RenderOptics.TranslucentRigid` is the stable class for Glass, Ice, solid QRTZ, DRIC, NICE, and RIME. Legacy powder Quartz remains `RoughGranular`. Keep the class in the existing palette alpha byte; it may lower display opacity and couple the existing coloured emission field into a proven dense exact-material body, but it must not change physics, material selection, support, alpha, or cavity eligibility. Exact Glass and Ice may additionally refract a coexisting native-wall backdrop: move only the allocation-free procedural wall-pattern coordinate, never the wall ID/texture sample, wall shape, wall alpha, particle alpha, or semantic ownership. Quantize the effect to world cells with no time term. Glass uses the signed material shoulder to bend one continuous asymmetric calibration card in opposite directions, while Ice averages stable opposing facets; the Glass optical centre remains undisplaced. Other translucent-rigid materials retain their ordinary treatment until explicitly classified. Canvas must source-over the unchanged particle alpha onto the independent wall plane; WebGL must alter only the existing final wall backdrop term, adding no texture, fetch, pass, upload, or backbuffer. Keep backdrop refraction on its own audit toggle so emission tint cannot satisfy the proof. The off→on→off composed gate must require bipolar low-bias redistribution across Glass shoulders and Ice, a repeat-stable off image, exact zero response on a separately wall-backed Metal control, and identical straight/refracted support. Unlike exact solids may share one categorical silhouette but still need a restrained optical contact: derive its signed direction from the same four compatibility samples, use it for RGB/normal response only, and never turn it into alpha, support, a dark separator, or an extra texture read. Canvas must evaluate that contact at its actual supersampled contour coordinates; WebGL may reuse the fourth `occupancyShape` component for the signed solid-only contact value because powder alone retains the support-count meaning. Dense exact Glass/Ice may reuse the existing signed solid-relief wave for a low-luminance-bias spectral split—coherent and stronger for Glass, opposed and weaker for Ice—with no new pattern, time term, sample, field, or allocation. Exact Glass/Ice may also add a separate bounded RGB-only lens shell from that existing relief plus already-computed edge light/Fresnel; every other material is an exact no-op and alpha/support remain unchanged. Keep contact/prism, refraction, and lens-shell audit toggles independent and prove off→on→off repeatability, chromatic Glass/Ice response, opaque-Metal zero, paired backend magnitude, and identical support. Canvas must still reject trait-bearing/emissive/thin/edge cells from dense emission coupling, preserve role accents above it, and use `EmissionField.mayLightWorldCell` so localized light avoids full-grid bilinear work; late WebGL promotion must inherit every toggle. When adding an optics class, update `RENDER_OPTICS_CLASS_COUNT`, the Canvas relief table allocation, class-exhaustion tests, README/render-lab documentation, and composed Glass/Ice clipping/hue probes together.
- Dense-scene Canvas performance claims require the audit-only full presentation timer, not only reconstruction/helper microbenchmarks. Enable it only for `inputAudit=1`, time from scheduled-field selection through the final composed `restore()`, warm the deterministic full-grid Metal fixture, and exclude samples that rebuilt atmosphere/liquid/emission fields when reporting steady-state presentation telemetry. Gas-light changes must also report a canonical atmosphere refresh that includes re-shading, `putImageData`, and final 2× composition; a helper-only profile does not cover that upload. ## Visual regression lab

Use the paused deterministic material atlas before and after material-shader changes:

```text
?scene=render-lab&renderScale=2
?scene=render-lab&renderScale=2&renderer=canvas2d
?scene=render-lab&simulation=native&renderScale=2
?scene=wall-lab&renderScale=2
?scene=wall-lab&renderScale=2&renderer=canvas2d
```

The render-lab query uses a 612×384 in-memory backend, does not restore or write autosave, and contains powder density ramps, an exact shallow settled-Sand slope, cohesive and sparse liquids, overlapping gas species, sand/water mixtures, adjacent liquid families, and representative rigid/organic/radioactive/emissive blocks. Keep canonical screenshots on this deterministic backend. The automated gate navigates separately to `simulation=native` for configured-source and LIFE smoke tests; never substitute native painting for the deterministic visual fixture. Capture the viewport itself at identical browser dimensions and keep local comparison shots under ignored `.artifacts/`.

Use the automated real-browser capture/interaction gate after shader or mapping changes:

```sh
mkdir -p .artifacts
npm run audit:browser-input -- --webgl-only --screenshot=.artifacts/render-lab-webgl.png
npm run audit:browser-input -- --canvas-only --screenshot=.artifacts/render-lab-canvas2d.png
```

The desktop gate performs a paired `renderScale=2` then `renderScale=1` navigation at the same explicit CSS viewport. It must report identical CSS canvas geometry while the backing changes only from 1224×768 to 612×384, and it repeats exact landmark painting, cursor-anchored wheel zoom, and 42×27 CSS-pixel middle-pan at 1×. Do not compare geometry captured under different device-emulation viewports; that tests browser setup rather than backing-scale independence.

The mobile gate must run for both Canvas2D and WebGL. The composed-output gate samples representative energy, dense solid, liquid, and gas regions. Keep dense fluid-core coverage, bounded luma range, and clipping checks in both Canvas2D and WebGL. The homogeneous lower Water/Oil/Acid/Lava columns additionally enforce bounded adjacent-pixel micro-contrast, nonzero five-by-five low-pass macro depth, stable family hue, a WebGL/Canvas macro-depth ratio of `0.65–2.0`, and a mean-exposure ratio of `0.65–1.6`; this rejects flat matte fill, raw-cell glitter, backend washout, or clipped Lava. Dense energy tiles must retain one dominant connected rendered body, while the high-energy core of the sparse PHOT strip retains quiet gaps. Keep explicit Smoke/Oxygen/Noble Gas hue assertions because uniform curvature math alone does not protect later additive composition. Prove gas lighting by capturing the identical canonical scene with only the gas-light coupling toggled off; source aura or intrinsic gas hue is not evidence. Semantic unit tests alone cannot prove that a shader, compositor, or fallback draw order still presents the field.

Framebuffer coverage must be measured against a stable same-geometry blank audit, not screenshot alpha or a raw RGB floor: composed page screenshots are opaque and the viewport background itself is nonzero. Wait for three identical frames separated by at least one field-refresh interval, record the canvas rectangle with every capture, reject canonical/control/blank rectangle drift, derive the per-region signal threshold from blank-frame noise, and count only canonical pixels that differ beyond it. Guard every post-navigation wait with the expected query stage so an old document cannot satisfy it. Keep matrix separators as zero-signal probes and preserve the separate semantic-mask/footprint checks for brush placement.

Liquid native-wall refraction may move only the analytic wall-pattern coordinate. Restrict ownership to authoritative semantic non-emissive liquid cells; reconstructed empty support has no trustworthy species/optics and must retain a straight backdrop, though it may stabilize phase-categorical shore classification for neighbouring semantic liquid. Read [`docs/render-lab.md`](docs/render-lab.md) before changing reconstruction thresholds or blur radii. A TypeScript or Vite build does not compile Pixi's runtime GLSL; a browser screenshot with a clean shader console is required.

The style lookup is an RGBA data texture, not display color: RGB stores phase/profile/emission and alpha stores the static `RenderTrait` mask. Keep nearest sampling and `no-premultiply-alpha`; zero-valued trait alpha must never erase the RGB metadata.

Canvas role styling belongs before the existing final pixel write. Reuse its fixed RGB scratch and per-frame clocks; do not reintroduce a post-composite typed-pixel read/clamp/write pass. Preserve the direct path for zero-trait, non-emissive fluids and keep animation residues/cadence stable when optimizing arithmetic.

Use it after wall ABI, wall texture, or compositing changes to prove that native walls remain distinct from particles and survive the same 612×384-to-2× presentation path.

## Project hygiene

- Use `apply_patch` for source and documentation edits.
- Keep heavy toolchains and caches such as emsdk and ccache project-local.
- Preserve the manual GitHub Actions build/build-and-deploy controls and successful-build-only ccache persistence.
- Native save sharing uses raw `GameSave::Serialise()` bytes in `.cps` files. Do not expand new saves into URL hashes or the clipboard; keep `.anifortpt` visibly separate for non-native fallbacks.
- A successful Pages upload is not enough evidence. Preserve the recursive local and live asset-closure checks, and browser-test the cache-busted deployment because stalled runtime initialization can look like a missing asset.
- The Pages artifact must contain `revision.txt` generated from `ANIFORTPT_REVISION`/`GITHUB_SHA`, and the post-deploy verifier must match it exactly before accepting the asset closure. A cache-busting query alone does not prove that Pages serves the requested commit.
- Do not permanently choose Canvas2D from a short Pixi initialization deadline. Pages cold loads can have WebGL2 and a valid Pixi chunk yet take more than 1.2 seconds to initialize. Mount the compatibility canvas promptly, expose the reason in the HUD/data attributes, and promote it in place when WebGL becomes ready.
- Clean up locally launched Chrome and Vite processes immediately after browser validation.
