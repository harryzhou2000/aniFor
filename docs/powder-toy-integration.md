# Powder Toy integration

## Current state

The default browser backend is the pinned official Powder Toy 100.0 simulation at revision `bde6b44edd8b6ef7b978fbdad3fb0bcb5f8a5939`, compiled as a single-threaded 612×384 ES-module WebAssembly target. `PowderToyBackend` owns its small C ABI; the compatibility C++ kernel and TypeScript backend are startup fallbacks.

`npm run build:wasm` fetches the pinned checkout, applies the reviewed headless Meson patch, copies the adapter and renderer-table definitions, compiles with project-local Emscripten and Meson, then publishes `stillroom_core.js` and `stillroom_core.wasm`. The headless target omits SDL UI, Lua, HTTP, pthreads, and Newtonian FFT gravity while retaining Powder Toy particle movement, native wall-grid physics, air, heat, element interactions, and ordinary vertical gravity.

## Projected material catalog

The frontend ABI defines 217 stable projected render IDs: ordinary IDs 1–170, IDs 171–194 for the 24 built-in `PT_LIFE` ctypes in upstream preset order, 22 nonselectable native-product projections at 195–216, and ordinary Broken Coal (BCOL) at 217. The UI catalog therefore exposes 171 ordinary brushes across powders, liquids, solids, gases, energy, explosives, special, radioactive, force, electronics, powered, sensors, and life; 166 are enabled in this headless build. It also lists all 22 native products as disabled, searchable reference tiles in their natural categories, so imported and reaction-created identities are discoverable without crossing the ordinary brush ABI. BCOL follows the reserved projection range to preserve every prior byte ID, but crosses the ordinary brush ABI and round-trips distinctly from Coal through OPS files. GRVT, GBMB, NBHL, NWHL, and GPMP remain visible but disabled because the headless engine intentionally omits Newtonian FFT gravity. Air-velocity-dependent behavior such as WHOL and VENT is marked as limited. `src/shared/materials.ts` is the catalog authority and `native/tpt/tpt_adapter.cpp` maps ordinary IDs bidirectionally while projecting valid LIFE `ctype` values through the dedicated range. Clone/source particles, radioactive and nuclear materials, force particles, seeds, plants, yeast, vines, and LIFE evolution therefore use native TPT semantics; representative tests verify projection, pressure, water stability, deterministic save/load, seed-driven plant growth, all 24 LIFE OPS round trips, and a B3/S23 blinker generation.

## Tool taxonomy

Catalog entries are typed as particles, walls, LIFE presets, signs, configured sources, or simulation tools rather than conflating TPT concepts. The current drawing surface exposes particle brushes—including native clone/source and force particles—sixteen true TPT wall-grid brushes through a separate `bmap` ABI, six configured-source tools, all 24 built-in LIFE tools, and native Air, Vacuum, Wind, Heat, Cool, and Sign tools. Fan is a native wall workflow: paint a connected Fan body, then complete a drag from it to configure that component's upstream `fvx`/`fvy` direction and strength. Fan-containing worlds run TPT's native air velocity update; worlds without a Fan retain the stable headless velocity-off mode. Fan vectors remain in native simulation state and serialise in standard OPS saves. Gravity wall remains visible but disabled because its separate gravity-field configuration ABI is not exposed. LIFE tools are capability-gated and call `powder_set_life(x, y, preset)`; they create native `PT_LIFE` only in empty matter cells, never route projection IDs through generic `powder_set`, never use LIFE painting as a source-target shortcut, and return without fallback when the capability is absent. Configured CLNE, BCLN, PCLN, PBCN, CONV, and CRAY use a target-first interaction: select an element, select the desired source tool, then draw. A compact `source → target` readout keeps the retained target explicit. The UI asks the native rule boundary before activation; self-targets, `PROP_NOCTYPEDRAW` elements, and PCLN/PBCN power-control targets remain inactive with an explicit unsupported-pair message instead of silently painting nothing. The adapter creates an empty source or reconfigures an existing source of the same type, calls that upstream element's `CtypeDraw`, and rolls back a newly created particle when TPT rejects the target. CRAY crosses the same native `CtypeDraw` boundary so target-default temperature and parameterized LIGH semantics remain native and save-stable. Source erasure remains ordinary erasure, and unavailable fallback backends never fall through to the previous particle brush. Air/Vacuum use TPT's ±0.05 pressure operation per brush pixel; Heat/Cool use ±2 K for ordinary particles and ±0.1 K for PUMP/GPMP. Wind consumes the raw drag segment rather than interpolated particle-brush points, clears inactive particle-authored coarse velocity when a new gesture begins, writes the authored `vx`/`vy`, and runs one normal air-update frame so diffusion, pressure coupling, clamping, and `WL_BLOCKAIR` semantics happen before particle advection. Ordinary frames return to `AIR_VELOCITYOFF` to retain the proven stable-water headless behavior. Vector-tool point samples explicitly no-op, so Wind can never paint the previously selected material. Native walls are rendered and serialized independently from particles, and their interactive dirty scan is bounded to the affected coarse-cell brush region. Signs live in `Simulation::signs` and cross a dedicated list/staging/CRUD ABI; they never occupy the particle or wall field. Selecting Sign and tapping empty space opens a compact 45-character editor, tapping an existing label edits it, and right-click or the mobile Eraser mode removes it. A pointer-events-free DOM annotation plane follows the renderer's existing world-to-CSS camera transform, while TPT expands native placeholders such as `{p}`, `{temp}`, and `{type}`. The 16-sign native limit, pointer justification, and OPS serialization remain upstream-authoritative.

## Save-file exchange

`GameSave::Serialise()` in the pinned engine produces modern `OPS1` bytes. `PowderToyBackend.saveFile()` exposes those bytes without base64 or URL expansion, and the UI downloads them with TPT's `.cps` extension. Import passes raw `.cps`/`.stm` bytes back through the native `GameSave` parser, which also recognizes legacy `PSv` and `fuC` signatures. Configured-source targets, LIFE presets, and signs remain ordinary native TPT state and therefore round-trip through stock TPT OPS files without a parallel JavaScript map or private save extension. TPT's own OPS parser remains the authority for sign text sanitation and its 45-character ceiling. A pending, unstepped Wind gesture is stored in the ordinary OPS velocity maps plus the optional namespaced `aniforTptWindPending` Boolean. Patched AniforTPT restores that one-frame intent, while stock TPT safely ignores the unknown optional field and still reads the standard air maps. Text `.anifortpt` files are reserved for startup fallback backends and are never labeled as native TPT saves. Local autosave continues to use the existing private string wrapper, and old hash links remain read-only migration inputs.

## Renderer contract

The adapter emits stable material/LIFE projection IDs, a full-resolution view of the native coarse wall grid, pressure, particle-temperature, and velocity fields. Powder Toy particle structs and numeric element/wall IDs remain inside the C++ boundary; the frontend owns only copied views and mutates native state through explicit, project-stable particle, LIFE, wall, configured-source, and simulation-tool functions. Configured-source readback returns an exact stable target ID only when the native type round-trips through the public mapping; it never reports a phase-projected approximation as an exact `ctype`. Invalid LIFE presets, source/tool IDs, coordinates, radii, and oversized vectors are rejected before they can contaminate native fields. The primary Pixi/WebGL presenter packs particles and walls into independent RGBA8 textures and reconstructs softened material fields in a palette/style-driven shader. The palette alpha byte carries one of 12 optical-response classes without adding a texture or pass. Aqueous, oily, corrosive, molten, and clean/sooty gas classes tune the volume shader; rough granular, smooth rigid, organic, device, and radioactive classes tune RGB-only solid surface response while canonical profiles remain a fallback. Reconstructed empty-space support deliberately uses the default class rather than guessing a material. Halo-aware 32-cell dirty regions bound static updates; dynamic temperature and velocity fields refresh at a 12 Hz ceiling when no particle edit otherwise requires a frame. The logical surface remains 612×384 while the default backing is 1224×768. Canvas2D consumes the same canonical lookup, optics, species-aware liquid RGBA, atmosphere, emission, and staggered-refresh infrastructure. It reconstructs only enclosed same-material solid holes and preserves unlike solid/liquid seams. A cold deployment can mount this compatibility view immediately before promoting in place to WebGL.
